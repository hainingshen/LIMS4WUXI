# 本地部署与 UI 验收计划

本文把本地部署、本地测试和 UI 对齐拆成可执行 goal。每个 goal 必须以可运行命令或可审阅截图结束；未通过本项 Verify 前，不继续扩散到下一项。

依据文档和参考：

- `00_技术栈与工程约定.md`
- `13_迭代里程碑与上线切换.md`
- `16_部署与发布手册.md`
- `22_开发执行TODO清单.md`
- `docs/UI/lims4wuxi-prototype.html`
- `docs/UI/lims4wuxi-style-preview.html`
- `docs/UI/prototype/*.jsx`
- `docker-compose.yml`
- `.env.example`

硬门禁：

- 本地部署必须走 Docker Compose，不手工启动散落进程作为验收依据。
- API 入口统一通过 Nginx：`http://localhost:8080/api/v1/*`。
- 内部端入口：`http://localhost:8080/internal/`。
- 客户门户入口：`http://localhost:8080/portal/`。
- UI 颜色、字体、卡片、标签、按钮和移动断点必须对齐 `docs/UI` 设计令牌。
- 桌面端使用 AntD，移动端使用 AntD Mobile；不得新增 Vue、Pinia、Flowable、Drools、MyBatis 等排除技术。
- 任何本地脚本不得要求提交密钥；密钥只能从 `.env` 或环境变量读取。
- 验收脚本失败时必须退出非 0，不能只打印警告。

## Goal-LD01 本地部署一键脚本与预检

Goal: 新开发机可用一组脚本完成本地部署预检、启动、停止和重置，避免每次手工拼命令。

Code slice:

```text
scripts/local/preflight.sh
scripts/local/up.sh
scripts/local/down.sh
scripts/local/reset.sh
deploy/README.md
```

脚本职责：

- `preflight.sh`：检查 Docker、Docker Compose、端口 `8080/9000/9001`、`.env`、必要镜像配置。
- `up.sh`：不存在 `.env` 时从 `.env.example` 复制，然后执行 `docker compose up -d --build`，并等待关键服务。
- `down.sh`：执行 `docker compose down`。
- `reset.sh`：二次确认后执行 `docker compose down -v --remove-orphans`，清空本地卷。

Verify:

```bash
scripts/local/preflight.sh
scripts/local/up.sh
curl -i http://localhost:8080/api/v1/auth/me
curl -I http://localhost:8080/internal/
curl -I http://localhost:8080/portal/
docker compose exec postgres psql -U lims -d lims \
  -c "select version, success from flyway_schema_history order by installed_rank desc limit 5;"
scripts/local/down.sh
```

通过标准：

- `/api/v1/auth/me` 无 token 返回 `401`。
- `/internal/` 和 `/portal/` 返回 `200`。
- Flyway 最新迁移成功。
- 停止脚本能正常退出。

## Goal-LD02 本地 Compose API 冒烟测试

Goal: Compose 启动后能用 HTTP 真实入口验证登录、基础配置、送检单和权限门禁。

Code slice:

```text
scripts/acceptance/local-compose-smoke.sh
```

覆盖：

- 内部账号 `internal.sales / Sales123!` 登录。
- 门户账号 `portal.applicant / Applicant123!` 登录。
- `/auth/me` 返回当前用户。
- 字典或表单 schema 能读取。
- 客户门户可保存/提交送检单最小草稿。
- 内部端可查询待受理数据。
- 无权限或未登录请求返回 `401/403`。

Verify:

```bash
scripts/local/up.sh
scripts/acceptance/local-compose-smoke.sh
scripts/local/down.sh
```

通过标准：

- 脚本退出码为 0。
- 每个关键请求打印方法、路径、状态码。
- 失败时输出响应 body 和 traceId。

## Goal-LD04 对齐现有页面到 `docs/UI` 原型

Goal: 当前已实现页面在桌面和移动端视觉上接近 `docs/UI`，信息密度和业务工具感一致。

Code slice:

```text

web-internal/src/styles.css
web-portal/src/main.tsx
```

对齐范围：

- 登录页：参考 `P1 客户门户登录` 和内部端入口，突出研究所、CNAS/CMA/GLP 可信信息。
- 内部端工作中心：参考 `P6 工作中心`，包含健康度、阻塞、Owner、趋势的扫描式布局。
- 样品收样台：参考 `P7 样品收样台`，强调扫码工作站、样品状态和操作按钮。
- 门户送检单：参考 `P3 送检单新建`，使用分组表单、双语字段、底部提交动作区。
- 移动端：参考 `M1-M4`，使用顶部 NavBar、列表入口、卡片摘要和 390×844 可用布局。

Verify:

```bash

(cd web-portal && pnpm build)
```

通过标准：

- 桌面 1440×900 无内容重叠。
- 移动 390×844 无横向滚动。
- 页面不出现大面积单色主题漂移。
- 表格、按钮、卡片、标签文字不溢出。

## 执行顺序

1. Goal-LD00：先封本文档。
2. Goal-LD01：先解决开发机可重复启动和重置。
3. Goal-LD02：在真实 Compose 入口上补 HTTP 冒烟。
4. Goal-LD03：抽取设计令牌，避免 UI 对齐时重复改色。
5. Goal-LD04：逐页对齐实际页面。
6. Goal-LD05：补视觉回归和一键总验收。
