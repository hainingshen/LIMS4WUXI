# 数据迁移与实施边界

## 1. 迁移原则

用户已确认一期需要迁移全部现有数据。考虑现有资料中存在字段缺失、格式不一致、历史数据质量不统一等情况，迁移应采用“先盘点、再清洗、后导入、可追溯校验”的方式执行。

迁移不是简单导库。迁移结果必须能支撑新系统运行，包括客户、项目、样品、报告、设备、标准品、人员、角色、模板和字典等基础数据。

## 2. 迁移范围

一期迁移范围包括：

- 客户和委托单位。
- 联系人、地址、报告接收、发票信息。
- 历史送检单。
- 历史协议、合同、补充协议。
- 历史项目和检测项目。
- 样品信息、样品照片、样品状态和流转记录。
- 协议变更申请、样品变更申请和其他关键字段变更记录。
- 留样记录、留样位置、到期和处置记录。
- 工作单和试验记录。
- 原始记录附件。
- 报告草稿、正式报告、签发记录。
- 报告数据中心索引、报告发放记录和批量下载痕迹。
- 设备台账和设备预约记录。
- 设备说明书、校准证书、检定证书、维护记录、SOP 等设备文件。
- 标准品、耗材、试剂台账。
- 出入库、领用、报废记录。
- 用户、角色、组织结构。
- 数据字典、系统配置和节假日。
- 报告模板和原始记录模板。
- 导入导出历史、迁移批次和旧状态映射。
- 档案索引和电子文件。

## 3. 迁移数据来源

已确认或预期的数据来源包括：

- 现有 LIMS 系统数据库或导出文件。
- 现有 LIMS 用户手册中对应模块数据。
- 客户、样品、协议、工作单、报告等历史业务数据。
- 仪器设备一览表。
- 标准物质一览表。
- 标准物质领用、验收、报废记录。
- 账号和角色资料。
- 本地或共享盘中的报告、原始记录、协议扫描件等电子文件。
- 对现有生产系统的只读盘点结果。

## 4. 迁移准备工作

迁移前需要完成：

- 确认现有系统数据库或导出权限。
- 确认附件文件存储位置和文件命名规则。
- 确认历史数据时间范围。
- 确认是否迁移已作废、已取消、测试数据。
- 建立旧字段到新字段映射表。
- 建立数据清洗规则。
- 建立迁移批次和回滚策略。
- 建立迁移结果验收标准。

### 4.1 分级兜底方案

迁移不能假定客户一定能提供数据库备份。系统设计期必须同时预留三种迁移模式：

| 等级 | 可获得资料 | 处理方式 | 系统要求 |
| --- | --- | --- | --- |
| A 级 | SQL 备份、数据库只读账号或标准导出 | 编写批量迁移脚本，保留旧 ID 和附件关联 | 建立字段映射、试迁移、正式迁移 |
| B 级 | Excel、Word、PDF、图片和零散附件 | 半自动导入，必要时 OCR 或人工校验 | 提供导入模板、错误清单、人工修正界面 |
| C 级 | 无法取得可用历史数据 | 上线后通过历史项目快速录入补建 | 提供 `MANUAL_LEGACY` 来源和历史档案录入口 |

三种模式都必须写入以下字段：

- `legacy_id`
- `source_type`
- `migration_batch`
- `data_quality_score`

数据质量低于阈值的历史记录可以归档为只读资料，不强行进入新系统主流程。

### 4.2 现有系统功能复用

现有 LIMS 中协议管理、样品流转单、工单管理、报告模板、检测子项、检测标准、检测项目、标准品库存等功能不能只作为迁移对象处理。新系统需按 `11_现有系统复用与重做策略.md` 判断哪些字段、编号和概念复用，哪些流程重写。

### 4.3 现有生产系统只读盘点基线

2026-05-14 以只读方式浏览现有生产系统，确认一期迁移不能只覆盖主流程，还需覆盖以下既有业务对象。以下数量仅作为迁移对象规模评估，不作为最终验收数量：

| 既有对象 | 只读盘点观察 | 迁移设计口径 |
| --- | --- | --- |
| 委托单位 | 列表约 58 条，工作中心客户卡片约 59 | 迁移到 `customer_org`、`customer_contact`，重复客户需清洗 |
| 协议 | 协议列表约 270 条，含变更申请入口 | 迁移到 `contract`，变更记录进入 `change_request` |
| 检测目录 | 检测项目约 600，检测子项约 374，检测标准约 256 | 迁移到检测项目、检测子项、检测标准三层模型 |
| 样品 | 样品约 540，样品流转单约 480，留样约 454 | 样品主数据进 `sample`，流转进 `sample_flow`，留样进 `sample_retention` |
| 工单 | 工单约 850，存在“我的工单”“待办工单” | 迁移到 `work_order`，历史工单低质量记录可只读归档 |
| 设备 | 设备约 845，预约记录约 113，存在设备文件管理 | 台账进 `device`，预约进 `device_booking`，附件进 `device_file` |
| 标准品 | 标准品信息约 292，含库存、出入库、预警 | 迁移到批次和库存流水 |
| 报告 | 报告模板约 16，报告数据中心可见历史报告 | 模板进 `report_template`，报告索引由报告、版本、发放日志和档案组合提供 |
| 主数据 | 组织架构、角色、用户、系统字典、节假日均有入口 | 迁移为系统基础数据，按新权限重新绑定 |

只读盘点还发现旧系统存在多种业务状态文本，例如“样品待接收”“暂存中”“检测进行中”“数据待复核”“报告待编制”“报告待提交”“报告待生成”“工单待确认”“工单执行中”“待执行”“执行中”“已结束”“待实验”“实验中”。这些状态必须进入 `legacy_status_mapping`，不得在导入脚本中临时硬编码。

## 5. 数据清洗重点

### 5.1 客户数据

需清洗：

- 客户名称重复。
- 中英文名称不一致。
- 联系人重复。
- 电话、邮箱、地址缺失。
- 发票信息缺失。
- 客户等级或行业字段不统一。

### 5.2 样品数据

需清洗：

- 样品名称和型号写法不一致。
- 批号缺失。
- 数量单位不统一。
- 储存条件缺失。
- 有效期和生产日期格式不统一。
- 样品照片缺失或未关联。

### 5.3 项目和检测项目数据

需清洗：

- 检测项目名称不统一。
- 检测依据和判定依据混用。
- 标准方法、无资质方法、非标方法未结构化区分。
- 业务负责人、技术负责人、检测员字段缺失。
- 历史状态无法直接映射新流程。

### 5.4 设备数据

仪器设备台账中存在空字段和格式不统一情况。需重点清洗：

- 设备编号。
- 设备名称。
- 规格型号。
- 出厂编号。
- 制造厂家。
- 使用地点。
- 负责人。
- 是否计量。
- 购买日期。
- 设备状态。

### 5.5 标准品和耗材数据

标准物质台账中存在二级编号、有效期、库存单位和备注信息不统一情况。需重点清洗：

- 编号和二级编号。
- CAS 号或货号。
- 批号。
- 浓度或纯度。
- 有效期限。
- 库存量和单位。
- 开瓶日期。
- 储存位置。
- 已用完、过期、报废状态。

### 5.6 用户和权限数据

账号资料中包含截图和个人信息。迁移时应注意：

- 不在开发文档中暴露个人手机号、邮箱等敏感信息。
- 用户账号可迁移。
- 密码不应明文迁移。
- 角色可按现有角色初始化。
- 组织架构尚在完善中，应允许后续调整。
- 人员资质和授权范围需后续补充。

### 5.7 旧状态映射

旧系统状态文本不能简单等同于新状态机状态。迁移时应按实体、来源页面和上下文映射，无法判断的进入 `MANUAL_REVIEW`。

| 旧系统状态文本 | 建议目标 | 迁移模式 | 说明 |
| --- | --- | --- | --- |
| 样品待接收 | `project.WAITING_SAMPLE`、`sample.WAITING_DELIVERY` | `ACTIVE_FLOW` | 样品未到且项目可继续等待 |
| 暂存中 | `sample.PRE_IN_STOCK` 或 `sample.IN_STOCK` | `MANUAL_REVIEW` | 需判断是否已完成正式入库 |
| 待实验 | `sample.READY_FOR_TEST`、`work_order.PENDING_EXECUTION` | `ACTIVE_FLOW` | 已具备试验条件但未开始 |
| 实验中、检测进行中 | `sample.IN_TESTING`、`work_order.IN_PROGRESS`、`project.IN_TESTING` | `ACTIVE_FLOW` | 需按工单粒度拆分 |
| 工单待确认 | `work_order.PENDING_CONFIRM` | `ACTIVE_FLOW` | 检测项目待确认 |
| 待执行 | `work_order.PENDING_EXECUTION` | `ACTIVE_FLOW` | 已分配或待分配需结合人员字段 |
| 执行中、工单执行中 | `work_order.IN_PROGRESS` | `ACTIVE_FLOW` | 进度和原始记录需同步迁移 |
| 数据待复核 | `work_order.RAW_REVIEWING` 或 `raw_record.REVIEWING` | `ACTIVE_FLOW` | 如缺少原始记录附件则降级人工复核 |
| 报告待编制、报告待生成 | `report.PENDING_GENERATE` | `ACTIVE_FLOW` | 工单完成后生成报告任务 |
| 报告待提交 | `report.DRAFT` 或 `report.QC_REVIEWING` | `MANUAL_REVIEW` | 需判断是否已提交 QC |
| 已结束 | `project.ARCHIVED`、`report.RELEASED` 或只读档案 | `MANUAL_REVIEW` | 旧系统“已结束”含义不唯一 |

### 5.8 补足模块清洗

补足既有生产功能时，需额外清洗以下内容：

- 变更申请：识别目标对象、变更字段、原值、新值、审批意见和生效时间；无法定位字段的变更作为附件归档。
- 留样：统一留样数量单位、保存条件、存放位置、留样期限和处置方式。
- 报告模板：按 `CONTRACT_EXPORT`、`SAMPLE_FLOW_EXPORT`、`REPORT`、`EN_REPORT`、`SPECIAL_REPORT` 分类，并标注自动化等级 `A/B/C`。
- 报告数据中心：不迁移成独立副本库，需补齐报告编号、版本、签发、发放、下载和档案索引。
- 设备文件：按说明书、校准证书、检定证书、维护记录、SOP、培训记录分类，标识当前有效版本和有效期。
- 导入导出记录：历史导出痕迹如无法取得，可从上线后新系统开始完整记录；迁移批次必须进入 `import_export_task` 或迁移日志。

## 6. 迁移实施步骤

建议迁移分为五步：

1. 数据盘点  
   列出所有数据表、附件目录、Excel 台账、Word/PDF 文件和历史报告。

2. 字段映射  
   建立旧系统字段、新系统字段、转换规则、是否必填、默认值、异常处理规则。

3. 清洗转换  
   处理重复、缺失、格式、单位、状态和附件关联问题。

4. 试迁移  
   选择小批量数据导入测试环境，验证客户、项目、样品、报告、设备、标准品链路是否完整。

5. 正式迁移  
   在上线窗口导入全量数据，完成抽样核验和业务验收。

## 7. 迁移验收标准

建议至少按以下标准验收：

- 客户数量与来源数据一致，重复客户有处理记录。
- 项目、合同、样品、报告能正确关联。
- 样品照片、原始记录、报告附件可打开。
- 历史报告编号不丢失。
- 设备编号唯一，预约记录能关联设备。
- 标准品库存和有效期可查询。
- 用户角色能登录并看到正确菜单。
- 旧状态能合理映射到新系统状态。
- 协议和样品变更记录能在统一变更中心中检索。
- 留样记录能按样品、项目、到期日查询。
- 报告模板、报告版本、报告发放日志和历史附件能互相追溯。
- 设备文件能挂接到设备详情，证书有效期可预警。
- 随机抽样项目可追溯到完整历史档案。

## 8. 一期实施边界

### 8.1 一期必须完成

- 主流程闭环。
- 三类项目流程区分。
- 非标报价前强制评审。
- 样品接收、入库、流转。
- 统一变更中心，覆盖协议、样品、项目和报告关键字段变更。
- 留样登记、到期预警和受控处置。
- 方案、试验计划、结果录入。
- 报告审核、签发、付款控制。
- 报告注册中心、模板版本管理和报告发放日志。
- 工作中心和进度可视化。
- 设备预约。
- 设备文件管理和证书有效期预警。
- 标准品和耗材基础库存。
- 受控导入导出任务。
- 电子档案长期保存。
- 全部历史数据迁移。

### 8.2 一期暂不完成

- 客户物流信息。
- 客户门户自助变更申请。
- 扫码出入库。
- 采购流程。
- 供应商填报。
- 完整财务结算。
- ERP 集成。
- 设备数据自动采集。
- 自动化实验排程。

## 9. 报告模板实施策略

报告自动生成应采用试点方式。用户已确认一期先以简单报告为模板，不直接覆盖所有报告类型。

建议实施策略：

- 先确定一个字段稳定、业务高频、审核路径清晰的简单报告。
- 建立报告模板字段映射。
- 建立原始记录到报告字段的数据来源。
- 先生成草稿报告。
- 经人工确认后进入 QC、QA、SD 审核。
- 试点稳定后再扩展其他报告模板。

## 10. 风险和控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 组织架构尚未最终确认 | 审批流人员无法完全配置 | 先建角色和流程，人员后续绑定 |
| 历史数据质量不统一 | 迁移周期增加 | 先做数据清洗和试迁移 |
| 客户无法提供数据库导出 | 迁移停摆 | 启用 A/B/C 三级兜底，至少支持 Excel/附件导入和历史项目快速录入 |
| 报告模板复杂度高 | 自动生成难度增加 | 简单报告先试点 |
| 旧状态含义不唯一 | 迁移后流程位置错误 | 建立 `legacy_status_mapping`，低置信度进入人工复核 |
| 留样和样品主状态混杂 | 样品处置不合规 | 留样独立建模，样品处置和留样处置分别留痕 |
| 报告数据中心被误做成副本库 | 报告版本失真 | 以报告、版本、发放日志和档案组合形成注册中心 |
| 设备文件缺少有效期 | 设备可用性判断失准 | 文件分类迁移，证书类文件必须补有效期或人工确认 |
| 非标项目评审信息不足 | 报价风险 | 强制技术、成本、周期字段和审批 |
| 未付款绿色通道滥用 | 财务和合规风险 | 固定审批、限定电子报告、全程留痕 |
| 设备内部覆盖外部预约 | 客户或外部用户体验风险 | 必须记录原因并通知相关人员 |

## 11. 建议交付物

一期开发建议形成以下交付物：

- 需求规格说明书。
- 业务流程图。
- 数据字典。
- 角色权限矩阵。
- 审批流程配置表。
- 数据迁移映射表。
- 旧状态映射表。
- 现有系统菜单和功能覆盖矩阵。
- 报告模板字段映射表。
- 设备文件分类和有效期清单。
- 留样迁移核验清单。
- 测试用例。
- 用户验收清单。
- 上线切换方案。
