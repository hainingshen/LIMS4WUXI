# 功能需求与数据清单

## 1. 模块总览

| 模块 | 一期目标 | 备注 |
| --- | --- | --- |
| 客户门户 | 客户提交送检信息、查看进度、查看草稿、付款后下载正式报告、确认协议 | 不做物流和变更申请 |
| 客户与委托单位 | 管理委托单位、联系人、报告和发票信息 | 需迁移现有客户数据 |
| 送检与项目受理 | 接收送检信息，完成内部核验和项目类型判断 | 支持无样受理 |
| 报价前评审 | 控制非标方法技术、成本、周期评估 | 未审批禁止报价签约 |
| 报价与合同 | 管理报价、合同、协议、评审、补充协议 | 三类项目走不同模板和声明 |
| 样品管理 | 样品接收、拍照、标签、入库、流转、退还或销毁 | 样品未到禁止试验下发 |
| 方案与试验计划 | 方案编制、审批、置样、试验计划 | 置样为独立任务 |
| 试验执行 | 任务领取、执行、结果录入、原始记录上传和审核 | 支持人工进度反馈 |
| 工作中心 | 项目状态、人员负荷、延期预警、问题跟踪 | 一期重点模块 |
| 报告管理 | 报告生成、审核、签发、草稿预览、正式发放 | 简单模板先试点 |
| 付款控制 | 未到账锁定报告和样品退还，绿色通道审批 | 审批记录归档 |
| 设备预约 | 半小时粒度预约，区分检测员和外部用户 | 不做深度排程 |
| 标准品和耗材 | 台账、库存、有效期、领用、预警、基础出入库 | 不做采购和扫码 |
| 统一变更中心 | 管理协议、样品、报告和项目关键字段变更 | 替代旧系统分散的变更申请列表 |
| 留样管理 | 登记留样、到期提醒、退还或销毁 | 作为样品生命周期独立节点 |
| 报告注册中心 | 正式报告检索、版本、二维码、发放和归档原件 | 承接旧系统报告数据中心 |
| 设备文件 | 管理设备证书、SOP、维护和校准资料 | 不做孤立网盘，绑定设备台账 |
| 档案管理 | 项目全过程记录归档，电子长期保存 | 纸质和业务记录按法规期限 |
| 组织权限 | 用户、角色、审批权限、数据权限 | 组织架构后续补齐 |
| 导入导出任务 | 主数据导入、迁移补录、受控导出和批量下载 | 所有批量操作留审计 |
| 数据迁移 | 全量迁移现有系统和台账数据 | 需数据清洗 |

## 2. 客户门户需求

### 2.1 客户可用功能

- 登录。
- 维护委托单位基础信息。
- 提交送检信息。
- 查看项目进度。
- 查看报告草稿。
- 确认或签署协议。
- 付款后下载正式报告。

一期客户门户默认不开放匿名注册。客户账号由内部创建或邀请开通。

客户角色：

- 委托单位管理员：可管理本单位账号，可查看本单位全部项目。
- 普通申请人：可提交送检信息，默认只查看本人提交项目。
- 只读用户：只查看被授权项目。
- 代理商账号：必须通过代理关系授权后才能查看多个委托单位项目。

### 2.2 客户不可用功能

- 不开放物流信息。
- 不开放变更申请。
- 不开放实验内部记录。
- 不开放内部审批意见。
- 不开放人员负荷和内部排期细节。

### 2.3 客户提交字段

客户提交字段应覆盖：

- 委托单位、制造商、联系人。
- 报告和发票信息。
- 样品名称、型号、批号、数量、状态、储存条件。
- 灭菌状态、包装、材料、用途。
- 检测项目、检测依据、判定依据。
- 报告语言、方案语言、GLP 要求。
- 剩余样品处理方式。
- 特殊说明。

## 3. 项目与合同需求

### 3.1 项目主数据

项目应至少包含：

- 项目编号。
- 来源送检单编号。
- 委托单位。
- 送检单号。
- 项目类型。
- 资质类型。
- 是否 GLP。
- 是否动物试验。
- 是否需要伦理审批。
- 是否需要非标报价前评审。
- 服务类型，普通或加急。
- 加急费比例，如适用。
- 加急承诺工作日，如适用。
- 合同或协议编号。
- 业务负责人。
- 技术负责人。
- SD。
- 当前状态。
- 计划完成日期。
- 实际完成日期。
- 付款状态。
- 报告状态。
- 归档状态。

项目和送检单关系：

- 一个送检单可以拆分为多个项目。
- 一个项目必须且只能来源于一个送检单。
- 一个项目可以包含多个样品、多个试验计划和多个工单。
- 一个项目可以有多个报告版本，但同一时间只能有一个正式有效报告。

审批岔路字段必须显式落在项目实体上，不能只保存在送检单备注中：

- `requiresGlp`
- `requiresAnimalTest`
- `requiresEthicsReview`
- `requiresNonstandardReview`

### 3.2 项目类型字段

项目类型必须结构化：

- 标准方法 + 有 CMA/CNAS 资质。
- 标准方法 + 无 CMA/CNAS 资质。
- 非标方法 / 客户提供方法。

不得仅用备注描述项目类型。

### 3.3 非标评审字段

非标评审应记录：

- 方法来源。
- 方法文件。
- 可行性结论。
- 技术风险。
- 质量风险。
- 所需设备。
- 所需动物。
- 所需耗材。
- 所需标准品或试剂。
- 是否分包。
- 人力成本。
- 材料成本。
- 分包成本。
- 预计周期。
- 技术负责人审批意见。
- 业务负责人审批意见。
- 审批时间。

## 8. 付款与绿色通道需求

一期付款确认由财务人员或出纳手工登记收款记录，不接 ERP、银行流水或自动对账。后续集成外部财务系统时，也应先写入收款记录，再由系统统一计算付款门禁状态。

### 8.1 付款状态

建议付款状态：

- 未付款。
- 部分付款。
- 已申请开票。
- 已到账。
- 绿色通道审批中。
- 绿色通道已通过。
- 绿色通道驳回。

### 8.1.1 收款记录字段

收款记录应作为独立实体，不得只在项目上勾选“已付款”：

| 字段 | 说明 |
| --- | --- |
| 收款编号 | 系统生成 |
| 项目编号 | 关联项目 |
| 报告编号 | 可选，按报告锁定时使用 |
| 到账金额 | 本次到账金额 |
| 到账时间 | 财务确认时间 |
| 收款方式 | 转账、现金、其他 |
| 登记人 | 财务人员或出纳 |
| 凭证附件 | 银行回单、截图或其他凭证 |
| 状态 | 已登记、已冲销 |
| 备注 | 异常说明 |

付款门禁按收款记录汇总判断，不允许前端直接修改报告下载权限。

## 13. 现有系统补足功能的取舍设计

本节用于承接生产系统只读盘点中发现但一期文档尚未充分展开的功能。新系统不按旧菜单机械复刻，而按以下原则处理：

- 有法规追溯、业务闭环或迁移验收价值的功能必须保留。
- 旧系统中分散但语义相同的功能合并到统一领域模型。
- 旧系统中只是文件夹或列表入口的功能，优先绑定到业务实体详情页。
- 批量导入、批量导出、模板下载等高风险操作必须受权限、审计和异步任务约束。

### 13.1 统一变更中心

旧系统中存在协议变更申请、样品变更申请等分散入口。新系统不建议继续拆成多个互不关联的变更模块，而是建立统一的 `change_request` 领域模型，再通过对象类型筛选形成不同视图。

一期应支持的变更对象：

- 送检单核心字段。
- 合同、协议和补充协议。
- 样品核心字段，例如批号、型号、数量、保存条件、检测项目。
- 报告相关字段，但报告签发后的更正必须进入重新签发或作废流程。
- 项目关键字段，例如服务周期、项目类型、资质声明、技术负责人。

变更规则：

- 合同或方案签署前，按权限允许直接修订并留审计。
- 合同或方案签署后，命中 `lock_policy=CHANGE_REQUEST` 的字段必须走变更申请。
- 报告签发后，`lock_policy=HARD_LOCK` 的字段不得直接修改，只能生成更正、作废或重新签发记录。
- 每次变更保存字段级 diff、变更原因、附件、审批记录和生效时间。
- 客户门户一期仍不开放客户自助变更申请；内部端可代客户发起并归档客户确认材料。

### 13.2 留样管理

留样不是普通样品备注，应作为样品生命周期的独立节点管理。现有系统的留样列表迁移到新系统后，应落到 `sample_retention`，并与样品、项目、报告和档案关联。

留样应记录：

- 样品编号、项目编号、报告编号，如已出报告。
- 留样数量、单位、保存条件、保存位置。
- 登记人、登记时间、预计保留至日期。
- 到期处理方式：退还、销毁、继续保留或转档案。
- 处理人、处理时间、处理凭证和审批记录。

留样状态建议：

- `PENDING_REGISTER`：待登记。
- `RETAINED`：已留样。
- `EXPIRING`：即将到期。
- `PENDING_DISPOSAL`：待处理。
- `RETURNED`：已退还。
- `DESTROYED`：已销毁。
- `ARCHIVED`：已归档。

留样退还、销毁仍受付款门禁和审批规则约束，不得绕过样品处置流程。

### 13.3 设备文件

设备文件管理有价值，但不应建设成独立网盘。一期应实现为“设备详情 - 文件/证书”能力，文件统一走文件元数据和对象存储。

设备文件类型包括：

- 设备说明书。
- 校准、检定或验证证书。
- 维护和维修记录。
- 期间核查记录。
- 设备 SOP。
- 培训或授权记录。

每份文件应记录文件类型、版本、适用设备、有效期、上传人、上传时间和是否当前有效。即将到期或已过期的证书应进入工作中心或通知提醒。

### 13.4 报告注册中心

旧系统“报告数据中心”本质是正式报告注册簿，不应只作为普通报告列表。新系统应以 `report`、`report_version`、`archive_item` 和发放日志组合实现报告注册中心。

报告注册中心应支持：

- 按委托单号、项目编号、报告编号、样品编号、流转单编号、委托单位和检测项目查询。
- 展示报告版本、状态、签发日期、发放日期、签章状态和付款门禁状态。
- 保存正式 DOCX、正式 PDF、签章文件、二维码校验信息和归档原件。
- 记录每次下载、发放、批量下载和客户查看行为。
- 对客户门户按数据权限只展示授权范围内的草稿预览和正式报告。

批量下载正式报告必须走异步任务并写审计日志，不允许前端直接拼接文件或绕过付款门禁。

### 13.5 报告模板管理分级

旧系统已有多类协议和报告模板。一期不承诺所有模板全部自动生成，但必须完成模板注册、版本和迁移保留。

模板分级：

| 等级 | 定义 | 一期处理 |
| --- | --- | --- |
| A 类 | 字段稳定、映射清晰、可自动生成草稿 | 建字段映射并接入报告生成 |
| B 类 | 基础字段可自动带入，但结论或过程依赖人工编辑 | 自动带入基础信息，人工补全 |
| C 类 | 历史模板或复杂专项模板，暂不适合自动生成 | 注册为模板文件，支持人工选用和历史查看 |

模板类型至少包括：

- 委托协议导出模板。
- 样品流转单导出模板。
- 通用中文报告模板。
- 英文报告模板。
- 专项报告模板，例如细胞毒性、皮肤吸收、力学、可浸提物、化妆品等。

模板发布必须保留 `template_code + template_version`，进行中的报告继续使用旧版本。

### 13.6 主数据和节假日

生产系统已有组织架构、用户、角色、系统字典和节假日管理。新系统一期应保留这些后台能力，但权限规则必须受控。

一期必须支持：

- 组织架构维护。
- 用户和角色绑定。
- 字典项维护和禁用。
- 节假日和工作日配置，用于服务周期、报告承诺时间和设备预约。
- 系统配置查看和受控编辑。

核心审批角色、权限矩阵和状态字典不允许管理员随意改坏流程。需要调整时应通过受控发布或数据库种子变更完成，并写入审计日志。

### 13.7 导入导出和批量任务

旧系统中存在导入、导出、批量导出、批量下载等入口。新系统应保留业务价值，但必须受控实现。

导入导出分类：

- 主数据导入：客户、检测项目、检测标准、设备、标准品等。
- 迁移补录导入：历史项目、历史样品、历史报告和附件索引。
- 普通列表导出：按当前查询条件导出可见字段。
- 正式报告批量下载：仅限付款门禁通过或内部授权范围。
- 审计或迁移核验导出：仅限质量、档案或系统管理员授权。

规则：

- 导入必须先预校验，输出错误清单，不得部分静默失败。
- 导入批次必须可追溯，写入 `migration_batch` 或导入任务号。
- 大批量导出和正式报告批量下载必须异步生成临时文件，并设置过期时间。
- 所有批量导入导出必须写入 `audit_log`。
