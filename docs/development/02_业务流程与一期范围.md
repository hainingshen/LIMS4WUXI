# 业务流程与一期范围

## 1. 总体流程

一期系统主流程如下：

客户送检信息 → 内部受理 → 项目类型判断 → 报价前评审 → 报价 → 合同/协议签署 → 样品接收 → 样品入库 → 方案编制 → 审批 → 试验计划 → 试验下发 → 试验执行 → 结果录入 → 原始记录审核 → 报告编制 → 报告审核 → 付款控制 → 报告发放 → 样品处置 → 档案归档。

## 2. 客户送检与受理

### 2.1 客户门户一期范围

客户门户一期开放：

- 提交送检信息。
- 查看项目进度。
- 查看报告草稿。
- 付款后下载正式报告。
- 确认协议或签署协议。

客户门户一期不开放：

- 物流信息。
- 变更申请。

### 2.2 送检信息

送检信息应覆盖现有送检单中的核心字段：

- 委托单位中英文名称、地址、联系人、电话、邮箱。
- 制造商信息。
- 报告接收邮箱、报告寄送信息、发票寄送信息。
- 报告语言、方案语言、GLP 要求、电子报告和纸质报告要求。
- 样品名称、规格型号、批号、数量、包装、储存条件、有效期、生产日期。
- 样品状态、颜色、密度、稳定性、溶解性、材料、包装材料。
- 样品预处理、灭菌状态、是否可裁剪、接触时间、浸提条件。
- 检测项目、检测依据、判定依据、特殊说明。
- 剩余样品处理方式。

客户提交的信息进入内部受理后，由业务人员或指定受理人员核验完整性。信息不完整时，不进入报价或合同流程。

## 3. 项目类型判断

系统必须在报价前完成项目类型判断：

1. 标准方法 + 有 CMA/CNAS 资质。
2. 标准方法 + 无 CMA/CNAS 资质。
3. 非标方法 / 客户提供方法。

项目类型判断影响：

- 报价规则。
- 合同模板。
- 合同评审内容。
- 报告声明。
- 签章规则。
- 归档要求。

## 4. 非标方法流程

非标方法或客户提供方法必须在报价和签约前完成以下流程：

非标申请 → 技术评审 → 成本评估 → 周期评估 → 技术负责人审批 → 业务负责人审批 → 允许报价 → 允许签约。

### 4.1 技术评审

技术评审确认：

- 方法是否可行。
- 实验室是否具备开展条件。
- 是否需要新增设备、动物、耗材、试剂或分包。
- 方法风险、质量风险和报告声明要求。
- 原始记录和报告模板是否需要新增或调整。

### 4.2 成本评估

成本评估确认：

- 人力成本。
- 动物成本。
- 耗材成本。
- 试剂或标准品成本。
- 分包成本。
- 其他特殊成本。

### 4.3 周期评估

周期评估确认：

- 试验周期。
- 排期和人员负荷。
- 设备占用。
- 外部资源周期。
- 预计交付时间。

### 4.4 系统门禁

未完成技术负责人和业务负责人审批时：

- 禁止生成正式报价。
- 禁止提交合同签署。
- 禁止样品进入试验流程。

## 5. 报价、合同与协议

### 5.1 标准有资质项目

标准有资质项目可走常规流程：

送检受理 → 项目匹配 → 报价 → 合同或协议 → 合同评审 → 签署 → 样品接收。

### 5.2 标准无资质项目

标准无资质项目必须使用对应合同模板、报告声明和签章规则。系统应明确标识该项目不属于 CMA/CNAS 资质覆盖范围，避免客户误解报告效力。

### 5.3 非标项目

非标项目必须先完成报价前评审。合同或协议中应明确：

- 客户提供方法或非标方法来源。
- 方法适用性责任边界。
- 是否具备资质声明。
- 试验风险。
- 交付周期。
- 增补费用触发条件。

### 5.4 补充合同

如项目执行过程中发生额外动物、耗材、分包、步骤或客户需求变化，系统应支持补充合同或补充协议记录。补充协议需关联原合同和原项目。

## 6. 样品接收与入库

### 6.1 无样受理

系统允许无样受理。样品未到时允许推进：

- 检品受理。
- 报价。
- 合同签订。
- 方案编制。

样品未到时禁止：

- 试验下发。
- 置样。
- 结果录入。
- 报告签发。

### 6.2 有样受理

样品到达后，样品管理员执行：

- 对照送检信息和合同信息。
- 核验样品名称、规格、批号、数量、包装、储存条件。
- 核验运输条件和冷链温度，如适用。
- 拍照上传，样品标签照片应能识别关键信息。
- 打印或生成样品标签。
- 记录异常并退回受理环节。
- 样品预入库。
- 样品正式入库。
- 更新库存和流转状态。

样品不一致时，不得直接进入试验下发。

### 6.3 置样

置样是独立任务节点。流程统一为：

- 需要置样：置样任务 → 置样记录 → 试验计划。
- 无需置样：直接进入试验计划。

所有项目最终都必须进入试验计划。

## 7. 方案、试验计划与试验下发

### 7.1 方案编制

方案编制可在无样受理状态下进行，但正式试验下发前必须完成样品核验。方案编制应包括：

- 检测项目。
- 检测依据和判定依据。
- 试验方法。
- 所需样品量。
- 所需人员、设备、试剂、标准品。
- 计划周期。
- 原始记录模板。
- 报告模板。

### 7.2 审批规则

一期必须启用真实审批角色：

- 所有项目必须走 SD。
- GLP 项目必须走 QA。
- 动物试验必须走伦理委员会。
- 报告必须走 QC → QA → SD → 签发。

### 7.3 试验下发条件

正式试验下发前必须满足：

- 合同或协议已签署。
- 样品已接收并核验通过。
- 必要置样任务已完成或确认无需置样。
- 方案已完成必要审批。
- 动物试验已通过伦理审批，如适用。
- 检测人员、设备和关键物料已确认。

资料不全时允许形成待下发任务，但不得进入正式试验执行。

## 8. 试验执行与结果录入

试验执行应支持：

- 检测人员领取任务。
- 样品领用和流转记录。
- 试验开始、暂停、继续、完成。
- 环境条件记录。
- 仪器设备记录。
- 标准品、试剂、耗材使用记录。
- 原始记录上传或在线填写。
- 结果数据录入。
- 结论填写。
- 原始记录复核。

原始记录复核不通过时，退回结果录入环节。

## 9. 项目进度与工作中心

工作中心一期应重点解决“看不见进度、看不见负荷、看不见风险”的问题。

应支持项目筛选、计划与实际进度、当前节点、人员负荷、进度反馈、风险预警、问题记录和责任人追踪。

一期不强制自动计算实验每个细分步骤的真实工时。理论工时、预计完成时间和人工进度反馈可作为一期基础方案。

工作中心详细规格和阈值以 `10_工作中心详细设计.md` 为准，必须包含健康度评分、结构化阻塞、唯一 Owner、超期通知和趋势快照。本文不重复定义扣分和预警阈值。

## 10. 报告编制与发放

### 10.1 报告编制

报告编制来源：

- 送检信息。
- 合同和协议。
- 样品信息。
- 检测项目和检测依据。
- 原始记录和结果数据。
- 报告模板。

一期报告自动生成先以简单报告模板试点，不一次性覆盖所有报告类型。

### 10.2 报告审核

报告审核固定为：

报告编制 → QC 技术审核 → QA 质量审核 → SD 最终审核 → 签发。

审核不通过时退回报告编制。

### 10.3 付款控制

默认未付款或未到账时，系统自动锁定：

- 正式纸质报告打印。
- 正式 PDF 下载。
- 电子签章报告发放。
- 样品退还、回寄或销毁。

允许继续：

- 试验执行。
- 结果录入。
- 报告编制。
- 草稿报告预览。

### 10.4 绿色通道

特殊情况下允许未到账先发电子正式报告，但必须审批：

绿色通道申请 → 部门负责人审批 → 管理层或总经理审批 → 系统临时解锁 → 发放电子正式报告。

绿色通道只解锁电子正式报告。纸质报告仍需到账后打印。

系统必须记录申请人、审批人、审批时间、审批意见，并归入项目档案。

## 11. 设备预约

一期设备预约规则：

- 检测员可提前 7 天预约。
- 外部用户可提前 2 天预约。
- 预约最小单位为半小时。
- 内部预约可覆盖外部预约，但应记录覆盖原因和操作人。
- 设备管理员、技术负责人、质量主管可查看和管理预约记录。

一期设备预约不强制与每一个实验步骤深度绑定，但内部检测员预约时应尽量关联工作单号和检测项目。

内部覆盖外部预约的默认实现：系统发送站内消息和邮件通知，被覆盖预约自动变更为“待重约”，并记录覆盖原因、操作人、操作时间和被覆盖预约。

## 12. 标准品、耗材和库存

一期只做核心功能：

- 台账。
- 库存。
- 有效期。
- 领用。
- 预警。
- 基础出入库。

一期不做：

- 扫码出入库。
- 采购流程。
- 供应商填报。
- 完整供应链。

系统应支持按有效期、库存下限、开瓶日期、存储条件进行提醒。

## 13. 档案归档

归档对象包括：

- 送检信息。
- 合同、协议、补充协议。
- 技术评审、成本评估、周期评估。
- 样品接收照片和异常记录。
- 样品流转记录。
- 方案和审批记录。
- 原始记录。
- 报告及审核记录。
- 付款和绿色通道记录。
- 样品处置记录。

保存规则：

- 报告、原始记录、委托单、合同保存至产品有效期结束后 6 年。
- 会议纪要、内部文件保存 6 年。
- 电子档案长期保存。
