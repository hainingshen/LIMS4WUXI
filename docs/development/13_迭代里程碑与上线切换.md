# 迭代里程碑与上线切换

## 1. 迭代原则

一期按可演示闭环拆分，不按菜单数量拆分。每个 Sprint 结束都应有可运行页面、接口和最小测试数据。

## 2. Sprint 划分

| Sprint | 目标 | 可演示功能 | 依赖 |
| --- | --- | --- | --- |
| S1 基础框架 | 登录、角色、字典、基础权限、CI/CD 蓝绿、PWA 骨架 | 内部和客户门户分别登录，按 roleCode 显示菜单；移动端响应式适配；蓝绿部署演练 | `00`、`07`、`16`、`roles.csv`、`dictionaries.csv`、JWT 短 TTL + Redis 黑名单 |
| S2 送检单 | 客户门户送检单 Ver.15 + formily 动态表单基础组件 | 客户提交送检单，内部受理，字段按 `form_schema` 运行时加载 | `08`、`submission_ver15_fields.csv`、`form_schema` 实体 |
| S3 项目与非标评审 | 项目拆分、项目类型、手写状态机 + `business_rule` 非标评审 | 非标项目未审批不能报价；规则可在后台修改并 1 分钟内生效 | `06`、Aviator 规则引擎、`business_rule` |
| S4 合同与样品 | 合同评审、样品接收、拍照、入库 | 无样受理，样品到达后核验和入库；移动端样品照片上传 | `12`、样品状态机 |
| S4.5 变更与留样 | 统一变更中心、留样登记、留样到期预警 | 协议/样品关键字段走变更申请；留样能登记、预警、退还或销毁 | `04`、`06`、`07`、`11` |
| S5 方案与工单 | 方案审批、待下发、工单执行 | 资料不全待下发，资料齐全后生成工单 | `06` 试验计划状态机 |
| S6 原始记录与报告试点 | 无菌原始记录、报告草稿、QC/QA/SD、OnlyOffice 接入、模板版本化 | 从无菌记录生成报告草稿并审核；PDF 通过 OnlyOffice 渲染；版式回归验收门禁 | `09`、`sterility_report_mapping.csv`、模板管理界面 |
| S7 付款门禁与绿色通道 | 收款记录、报告发放控制 | 未付款锁定正式报告，绿色通道只发电子版 | `04`、`06`、`permission_matrix.csv` |
| S7.5 报告注册与模板 | 报告注册中心、报告发放日志、报告模板分级、设备文件 | 已签发报告能按版本和发放记录检索；模板按 A/B/C 管理；设备证书到期预警 | `06`、`07`、`09`、`17` |
| S8 工作中心 | 健康度、阻塞、Owner、趋势；`system_config` 阈值后台可调 | 项目变黄变红、阻塞录入、人员负荷；管理员后台改阈值 1 分钟生效 | `10`、`system_config` |
| S9 迁移与上线 | A/B/C 迁移、历史数据抽样验收、导入导出任务、等保二级合规检查 | 导入客户、样品、设备、标准品、历史项目、留样、报告模板和设备文件；通过等保检查清单 | `05`、`11`、`16 §10` |

## 3. 上线切换步骤

1. 确认现有系统数据出口等级：A、B 或 C。
2. 建立试迁移环境。
3. 导入基础字典、角色、权限和测试目录。
4. 迁移客户、人员、设备、标准品等主数据。
5. 迁移历史项目、样品、报告和附件。
6. 抽样核对历史档案。
7. 冻结旧系统新增业务。
8. 正式迁移增量数据。
9. 新系统开放客户门户和内部端。
10. 上线后一周内每日检查付款门禁、报告发放、样品流转和工作中心预警。

## 4. 最小验收脚本

一期至少跑通以下脚本：

1. 客户提交标准有资质项目送检单。
2. 内部受理并生成项目。
3. 样品未到时允许方案编制但不能试验下发。
4. 样品到达后完成接收、拍照、入库。
5. 发起样品关键字段变更，审批通过后生效并写入审计。
6. 登记留样，到期前生成预警。
7. 方案审批后生成工单。
8. 检测员执行无菌检查并提交原始记录。
9. 生成无菌报告草稿。
10. QC、QA、SD、授权签发完成。
11. 报告注册中心可检索当前版本、历史版本和发放日志。
12. 未付款时客户只能预览草稿，不能下载正式 PDF。
13. 财务登记到账后客户下载正式报告。
14. 样品退还或销毁完成并归档。
15. 工作中心显示项目健康度和完整时间线。
