# LIMS 管理系统项目基础开发说明

## 1. 文档定位

本文档作为无锡生物所 LIMS 管理系统的一期基础开发依据，用于统一客户实际业务需求、一期建设边界、核心流程、审批门禁和系统模块范围。

本文档不以通用 LIMS 产品功能为目标，不扩大为完整 ERP、采购、供应链或财务系统。一期重点是打通客户委托到报告交付的主流程，并围绕该主流程补齐样品、试验、报告、进度、设备预约、标准品库存和基础数据迁移能力。

面向代码生成和实施落地时，应同时使用 `00_技术栈与工程约定.md`、`06_数据模型与状态机.md`、`07_API与界面契约.md` 以及对应字段映射表。本文件偏业务口径，不替代状态机、接口和数据库字段规约。

## 2. 依据材料

本次梳理依据以下资料形成：

- 第一次开发会会议纪要与语音转录。
- 客户送检单、委托协议、合同评审单、分包协议、技术合作协议。
- 标准方法与非标方法流程图。
- 样品接收与入库、试验执行与结果录入、报告编制与归档流程图。
- 现有 LIMS 用户手册。
- 样品流转单、原始记录模板、报告格式作业指导书、报告样例。
- 设备预约教程、设备预约新增功能说明、仪器设备台账。
- 标准物质台账、验收、领用、报废记录。
- 项目可视化参考材料。
- 2026-05-13 用户补充确认意见。

## 3. 一期建设目标

一期目标是建立一套可实际运行的 LIMS 主流程系统，覆盖以下业务闭环：

客户提交送检信息 → 项目类型识别 → 技术或合同评审 → 报价与签约 → 样品接收与入库 → 方案编制 → 试验计划 → 试验执行与结果录入 → 原始记录审核 → 报告编制 → QC/QA/SD 审核 → 付款控制 → 报告发放 → 样品处置 → 档案归档。

一期系统应解决当前客户反馈中最明确的痛点：

- 销售、技术、合同、样品、实验、报告信息重复录入。
- 非标方法在报价和签约前缺少强制技术、成本、周期评估。
- 项目执行进度、人员负荷、延期风险不透明。
- 样品接收、照片、入库、流转、退还缺少完整追踪。
- 报告自动生成和审核流程弱，正式报告发放缺少付款门禁。
- 设备预约和标准品库存有独立管理需求，但一期不做深度自动化绑定。
- 现有系统数据需要整体迁移，但需同步清洗和补齐主数据。

## 4. 一期系统建设原则

### 4.1 以真实工作流为准

系统流程以客户实际业务和已确认制度为准。现有系统、通用 LIMS 模板和第三方产品功能只能作为参考，不能替代客户已确认的工作流。

### 4.2 先主流程，后扩展

一期优先保证委托、样品、试验、报告、归档主链路闭环。设备、标准品、库存、客户门户、数据迁移均服务于主流程，不在一期扩展为采购、ERP、财务核算或完整供应链。

### 4.3 审批门禁必须可控

非标方法、合同签署、试验下发、报告签发、未付款发报告等关键节点必须由系统强制控制，不能只依赖线下口头确认。

### 4.4 先做到可追溯，再逐步自动化

一期对进度、设备、库存、报告模板等功能采用实用方案。能通过人工录入、状态更新、审批记录和附件归档实现闭环的，不在一期强行做复杂算法或深度设备联动。

## 5. 一期范围

一期纳入以下模块：

- 客户门户。
- 客户与委托单位管理。
- 送检信息与委托申请。
- 项目类型识别与报价前评审。
- 报价、合同、协议、合同评审。
- 样品接收、拍照、标签、入库、流转、处置。
- 方案编制、试验计划、试验下发。
- 试验执行、结果录入、原始记录上传和审核。
- 项目工作中心、进度看板、人员负荷、延期预警。
- 报告模板、报告自动生成试点、报告审核和签发。
- 付款状态控制、绿色通道审批。
- 设备预约。
- 标准品、耗材基础库存。
- 档案归档和长期电子保存。
- 组织、角色、权限、审批流。
- 现有系统数据迁移。

## 6. 一期不纳入范围

以下内容不作为一期开发目标：

- 完整采购流程。
- 供应商在线填报。
- 扫码出入库。
- 完整供应链管理。
- 完整财务系统或 ERP 集成。
- 设备数据自动采集。
- 设备预约与实验步骤的深度自动排程。
- 客户物流信息管理。
- 客户在线变更申请。
- 大规模 AI 自动判读实验结论。

## 7. 项目类型定义

系统必须把项目明确分为三类，并分别控制流程、模板、声明、签章和归档：

| 类型 | 定义 | 一期处理原则 |
| --- | --- | --- |
| 标准方法 + 有 CMA/CNAS 资质 | 方法属于标准方法，且实验室具备相应资质 | 可走常规报价、合同、报告和签章流程 |
| 标准方法 + 无 CMA/CNAS 资质 | 方法为标准方法，但不在实验室资质范围内 | 合同、报告声明、签章和归档要求单独控制 |
| 非标方法 / 客户提供方法 | 客户提供方法或项目不属于既有标准方法 | 报价和签约前必须完成技术评审、成本评估、周期评估和审批 |

## 8. 关键业务门禁

| 门禁 | 系统控制要求 |
| --- | --- |
| 非标方法报价 | 未完成技术负责人和业务负责人审批，禁止报价、禁止签约 |
| 样品未到 | 允许报价、合同、方案编制；禁止试验下发、置样、结果录入、报告签发 |
| 试验下发 | 必须满足合同或协议已完成、样品已核验、必要审批已通过 |
| 动物试验 | 必须通过伦理委员会审批后才能正式下发 |
| 报告审核 | 必须经过 QC → QA → SD → 签发 |
| 未付款 | 默认禁止正式纸质报告、正式 PDF、电子签章报告和样品退还 |
| 绿色通道 | 仅可审批后先发电子正式报告，纸质报告仍需到账后打印 |
| 档案保存 | 纸质和业务记录按类型保存，电子档案长期保存 |

## 9. 一期验收方向

一期验收不以功能数量为核心，而以真实业务闭环为核心。建议至少满足以下验收条件：

- 能完成一个标准有资质项目从送检到报告发放的完整流程。
- 能完成一个非标项目报价前技术、成本、周期评审并形成审批记录。
- 能完成样品接收、照片、标签、入库、流转和处置记录。
- 能完成方案、试验计划、结果录入、原始记录审核。
- 能完成报告编制、QC/QA/SD 审核、付款门禁、正式报告发放。
- 能在工作中心看到项目状态、人员负荷、进度风险和超期提醒。
- 能按半小时粒度完成设备预约，并区分检测员和外部用户预约规则。
- 能完成标准品基础出入库、领用、有效期和库存预警。
- 能导入现有客户、项目、样品、设备、标准品、人员和历史业务数据。
