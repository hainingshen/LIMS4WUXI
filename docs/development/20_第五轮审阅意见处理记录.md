# 第五轮审阅意见处理记录

## 1. 背景

本轮来自对现有生产系统的只读比对和后续文档审阅。只读范围包括工作中心、协议管理、检测目录、样品流转、工单、设备、标准品、样品、留样、报告模板、报告数据中心、委托单位和主数据管理。

本轮目标不是照搬旧菜单，而是判断现有业务是否能被一期新系统完整迁移，并补足有价值的业务能力。

## 2. 从生产系统比对中确认的缺失

| 缺失项 | 旧系统表现 | 新系统处理 |
| --- | --- | --- |
| 协议变更、样品变更 | 旧系统存在分散变更申请入口 | 合并为统一变更中心 `change_request` |
| 留样管理 | 旧系统存在留样列表和处置痕迹 | 独立建模为 `sample_retention` |
| 报告数据中心 | 旧系统提供历史报告查询 | 重做为报告注册中心，不建立报告副本库 |
| 报告模板管理 | 旧系统约 16 类模板 | 注册为 `report_template`，按 A/B/C 自动化等级分级 |
| 设备文件管理 | 旧系统有设备文件入口 | 绑定设备详情，形成 `device_file` |
| 导入导出和批量下载 | 旧系统存在列表导出和历史数据处理需求 | 重做为 `import_export_task` 异步任务 |
| 旧状态文本 | 旧系统有多套业务状态文本 | 建立 `legacy_status_mapping`，低置信度进入人工复核 |
| 主数据和节假日 | 旧系统有组织、角色、用户、字典、节假日管理 | 保留为主数据管理，纳入权限和审计 |

## 3. 已采纳的设计决策

| 决策 | 处理位置 | 结论 |
| --- | --- | --- |
| 统一变更中心 | `03`、`04`、`06`、`07`、`11` | 采纳。用字段级 diff、锁定策略和审批后生效替代旧系统分散变更菜单 |
| 留样独立生命周期 | `03`、`06`、`07`、`11` | 采纳。避免把留样作为样品备注造成合规风险 |
| 报告注册中心 | `03`、`06`、`07`、`11` | 采纳。由报告、版本、发放日志、档案组合形成注册簿 |
| 报告模板分级 | `03`、`06`、`07` | 采纳。一期先注册、版本化和分级，不承诺全部模板自动生成 |
| 设备文件嵌入设备详情 | `03`、`06`、`07`、`11` | 采纳。设备文件不做独立网盘 |
| 导入导出任务 | `03`、`06`、`07`、`11` | 采纳。批量操作必须异步化、可追溯、可审计 |
| 旧状态映射 | `05`、`06` | 采纳。迁移脚本不得硬编码状态文本 |
| `report_template_id` 外键 | `06` | 采纳。`report` 新增可空外键，同时保留 code/version 快照 |
| 统一变更生效 SLA | `17` | 采纳。区分软锁、审批后生效、硬锁流程 |
| 原型新增页面 | `19` | 采纳。追加统一变更、留样、报告注册、模板、设备文件、主数据、导入导出页面 |
| 迭代里程碑对齐 | `13` | 采纳。新增 S4.5 和 S7.5，迁移 Sprint 覆盖补足模块 |

## 4. 显式不采纳的旧系统照搬方式

| 旧方式 | 不采纳原因 | 新方式 |
| --- | --- | --- |
| 协议变更和样品变更做成两个孤立菜单 | 同类变更逻辑重复，权限、锁定、生效难统一 | 统一变更中心 + 按目标对象筛选 |
| 报告数据中心做成报告副本库 | 容易造成正式报告、历史版本和归档件不一致 | 报告注册中心引用报告版本、发放日志和档案 |
| 设备文件做成独立文件柜 | 脱离设备台账后难判断证书有效期和设备可用性 | 设备详情内嵌文件和证书 Tab |
| 导入导出作为普通列表按钮 | 容易绕过权限和审计，失败不可追溯 | 导入导出任务，预校验、异步执行、结果文件、过期清理 |
| 旧状态直接写入新状态字段 | 旧状态语义不唯一，容易污染新流程 | `legacy_status_mapping` + 人工复核 |

本轮审阅意见主体合理。Markdown 层和机读规约层的主要缺口已在第五轮和开工前最终补齐中完成。后续启动 Vibe Coding 或 S1 开发时，应优先以 `specs/openapi.yaml`、`specs/dictionaries.csv`、`specs/permission_matrix.csv` 和 `specs/fixtures/demo_project.json` 为准，避免再从 Markdown 散文中推断接口、枚举或权限。
