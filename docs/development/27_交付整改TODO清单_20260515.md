# LIMS4WUXI 交付整改 TODO 清单（2026-05-15）

## 1. 目标和执行原则

本文基于以下复测材料和当前 `main` 环境抽样复核结果制定：

- `25_可交付系统复测缺口清单_20260515.md`
- `26_岗位工作流复测缺口清单_20260515.md`
- 当前本地 `main` 验证结果和关键 API 抽样复核

目标不是把报告里的每一条描述机械改完，而是把系统推进到“最终用户可实际使用、能完成岗位工作、能创造业务价值、能安全交付”的状态。

执行原则：

- 先修交付阻断安全问题，再修岗位闭环，再修体验和生产化。
- 每个 TODO 必须有明确可演示结果、代码范围和验收方式。
- 服务端权限和数据范围是唯一可信边界，前端只负责展示服务端允许的数据。
- 所有新问题必须进入自动化验收，不能只靠人工复测。
- 自动化 smoke 数据必须隔离，不能继续污染人工验收环境。

## 3. P0 交付阻断项

### TODO-P0-01 门户客户数据隔离和 IDOR 防护

问题描述：

- `portal.applicant` 当前可见跨客户项目、送检单、报告和合同。
- 门户普通申请人应默认只看本人提交项目；客户单位管理员只看本单位；只读用户只看授权范围。
- 当前 API 列表和前端提示不是同一套授权规则，属于客户数据泄露风险。

用户价值：

- 客户门户上线的最低安全要求是客户只能看到自己的业务数据。
- 修复后系统才具备给外部客户开放的基础。

开发思路：

- 新增统一的 `PortalAccessPolicy` 或等价领域服务，集中判断门户用户对 `submission/project/report/contract` 的列表、详情、预览、下载权限。
- 修正客户申请人创建送检单时的客户组织归属：不能无条件生成新 `customer_org` 后又按账号固定组织过滤；需要明确是“本人提交”还是“本单位代理提交”。
- 对门户列表接口强制服务端注入当前用户和当前客户组织范围，不接受前端传来的客户范围作为可信输入。
- 对详情接口补齐按 ID 授权校验，未授权返回 403，不存在返回 404。
- 对门户页面移除“先展示全量列表再提示未授权”的逻辑。

建议代码切片：

```text
backend/src/main/java/com/njxs/lims/portal/
backend/src/main/java/com/njxs/lims/project/api/ProjectController.java
backend/src/main/java/com/njxs/lims/project/persistence/JdbcProjectRepository.java
backend/src/main/java/com/njxs/lims/submission/service/SubmissionApplicationService.java
backend/src/main/java/com/njxs/lims/report/service/ReportService.java
backend/src/main/java/com/njxs/lims/contract/api/ContractController.java
web-portal/src/PortalProjectOverviewPage.tsx
web-portal/src/main.tsx
scripts/acceptance/workflow-gap-regression.sh
```

验收方案：

- 使用两个不同客户组织的门户账号创建数据。
- 门户 A 调用 `/projects`、`/submissions`、`/reports`、`/contracts` 不得返回门户 B 数据。
- 门户 A 猜测门户 B 的 ID 访问详情、预览、合同确认和下载接口必须返回 403 或 404。
- Playwright 验证未授权详情页显示明确 403，不展示其他客户列表或下载按钮。

通过标准：

- `workflow-gap-regression.sh` 新增 IDOR 用例全部通过。
- `portal.applicant` 查询结果中不存在非授权 `customerOrgId`。

### TODO-P0-02 正式报告 PDF 下载授权和发放审计闭环

问题描述：

- 门户客户当前可通过报告 ID 下载非本客户正式报告 PDF。
- 报告下载只校验付款门禁是不够的，还必须校验客户归属和授权范围。

用户价值：

- 正式报告是客户核心交付物，必须防止跨客户下载。
- 修复后报告发放日志才具备合规审计价值。

开发思路：

- 在 `ReportPdfService.downloadOfficialPdf` 入口增加报告归属授权校验。
- 授权条件至少包括：报告所属项目客户、当前门户用户身份、客户组织范围、本人提交范围、显式授权范围、付款或绿色通道状态。
- 内部用户下载也应按角色和数据范围记录发放日志，避免内部全员可下载。
- 发放日志区分 `PREVIEW`、`OFFICIAL_DOWNLOAD`、`INTERNAL_DOWNLOAD`、`GREEN_CHANNEL_RELEASE`、`PAYMENT_UNLOCK_RELEASE`。

建议代码切片：

```text
backend/src/main/java/com/njxs/lims/report/service/ReportPdfService.java
backend/src/main/java/com/njxs/lims/report/persistence/JdbcReportRepository.java
backend/src/main/java/com/njxs/lims/report/delivery/service/ReportDeliveryLogService.java
backend/src/test/java/com/njxs/lims/report/
scripts/acceptance/workflow-gap-regression.sh
web-portal/src/reportPresentation.ts
```

验收方案：

- 客户 A 已付款报告下载返回 200。
- 客户 B 尝试下载客户 A 报告返回 403。
- 未付款报告返回 423 `PAYMENT_GATE_LOCKED`。
- 绿色通道报告只解锁电子正式报告，并写入绿色通道发放日志。
- 下载日志包含下载人、客户范围、报告版本、付款门禁状态。

通过标准：

- 跨客户正式报告下载不再返回 200。
- 每次成功下载都能在发放日志中追溯。

### TODO-P0-05 动作接口权限、资源和请求体校验顺序统一

问题描述：

- 多个动作接口对无权用户先返回 400 字段校验，或对未支持写动作返回 500。
- 有权角色用假 ID 探测时部分返回 403，而不是 404，说明数据范围和资源存在性边界不清晰。

用户价值：

- 前端可以稳定处理错误。
- 安全测试可以明确区分无权、无资源、状态不满足和请求体错误。

开发思路：

- 建立动作接口统一处理规范：认证 -> 授权 -> 资源存在/归属 -> 状态机 -> 请求体校验 -> 执行动作。
- 对所有 `@RequiresAction` 动作补充无权角色测试。
- 对无实现的 HTTP method 返回 405 或明确 404，不能进入 500。
- `GlobalExceptionHandler` 覆盖常见 Spring MVC 异常、方法不支持、JSON 解析、参数校验。

建议代码切片：

```text
backend/src/main/java/com/njxs/lims/common/web/GlobalExceptionHandler.java
backend/src/main/java/com/njxs/lims/permission/PermissionService.java
backend/src/test/java/com/njxs/lims/permission/
scripts/acceptance/workflow-gap-regression.sh
```

验收方案：

- 无 token 返回 401。
- 无权角色动作返回 403。
- 有权角色操作不存在 ID 返回 404。
- 有权角色操作状态不满足返回业务错误。
- 有权角色请求体错误返回 400。
- 所有场景不出现 500。

通过标准：

- `workflow-gap-regression.sh` 覆盖关键动作错误码矩阵。

## 4. P1 岗位工作流闭环

### TODO-P1-01 销售工作台闭环

问题描述：

- 销售缺少聚焦“待受理、待报价、待合同、待客户确认”的工作台。
- 销售受理、拆分、非标评审启动等动作权限和数据范围需要按岗位闭合。

开发思路：

- 增加销售工作台 API，按当前销售列出待处理事项。
- 送检单受理、项目拆分、报价、合同发起和客户确认状态串联。
- 项目详情突出销售需要的信息：客户、送检单、报价、合同、当前卡点。

验收方案：

- 客户提交送检单后，销售待办出现。
- 销售受理并拆分项目。
- 标准项目进入报价；非标项目进入技术/业务评审。
- 合同签署后样品管理员收到后续待办。

### TODO-P1-02 技术负责人和业务负责人非标评审闭环

问题描述：

- 非标技术和业务评审缺少清晰待办和审批链。
- 接口行为不能证明技术负责人、业务负责人各自职责。

开发思路：

- 非标评审拆成技术评审和业务评审两个阶段。
- 技术评审记录方法、设备、人员、周期、风险和附件。
- 业务评审记录报价边界、周期风险、客户风险。
- 审批结果进入项目状态机和审批记录。

验收方案：

- 销售发起非标评审。
- 技术负责人收到待办并审批。
- 业务负责人收到待办并审批。
- 未双审批通过前报价接口返回业务错误。

### TODO-P1-04 检测员工作单和原始记录闭环

问题描述：

- 检测员当前看到全量工单，不是本人工作单。
- 设备预约、领样、开始、暂停、完成、原始记录提交未形成岗位闭环。

开发思路：

- 设备预约支持检测员 7 天规则并可关联工作单。

验收方案：

- 技术负责人派工给检测员 A。
- 检测员 A 可见并开始工单，检测员 B 不可见或不可操作。
- 检测员提交原始记录后，QC 待办出现。

### TODO-P1-05 QC、QA、SD 审核队列闭环

问题描述：

- 审核角色缺少待审队列、退回队列和已审历史。
- QC/QA/SD 的数据范围和审核阶段区分不明显。

开发思路：

- 建立审核任务查询接口，按角色返回待审 raw record、report、study plan。
- QC 复核原始记录和报告技术审核。
- QA 处理 GLP/质量审核。
- SD 审核方案和报告最终审核。
- 审核意见写入 `approval_record`。

验收方案：

- 原始记录提交后 QC 待办出现。
- QC 通过后报告编制待办出现。
- 报告依次经过 QC、QA、SD。
- 驳回会回到正确岗位并记录原因。

### TODO-P1-06 报告编制和授权签发闭环

问题描述：

- 报告编制员缺模板选择、草稿编辑、提交 QC 和退回修改闭环。
- 授权签字人缺待签发队列和签发审计。

开发思路：

- 增加报告模板管理页面深链和模板版本选择。
- 报告草稿生成后可预览、编辑、提交 QC。

验收方案：

- QC/QA/SD 后授权签字人签发。

### TODO-P1-07 财务收款和绿色通道闭环

问题描述：

- 财务工作台缺待收款、凭证上传、解锁、冲销和异常处理。
- 绿色通道审批状态和解锁范围需要业务化展示。

开发思路：

- 财务只看应收、收款、解锁相关数据。
- 付款凭证走真实文件上传。
- 付款到账触发报告和样品处置门禁解锁。
- 绿色通道明确只解锁电子正式报告，纸质报告和样品处置仍受规则控制。

验收方案：

- 财务上传收款凭证。
- 报告付款门禁解锁。
- 客户可下载本客户报告。
- 绿色通道审批链写入审批记录和发放日志。

### TODO-P1-08 设备、库存、档案岗位闭环

问题描述：

- 设备文件需要真实上传，不应手填 `fileId`。
- 设备预约覆盖缺终态保护。
- 库存缺低库存、近效期、领用和项目关联。
- 档案页面裸 UUID 过多，无法业务化使用。

开发思路：

- 设备管理员上传真实校准证书/SOP/维护记录，系统记录有效期和预警。
- 预约覆盖对 `NEEDS_RESCHEDULE`、`CANCELLED`、`COMPLETED` 禁用重复覆盖。
- 库存批次支持有效期、开瓶日期、库存下限、领用、退回、报废、盘点。
- 档案项展示客户、项目号、报告号、档案类型、保管期限，不以 UUID 为主。

验收方案：

- 上传设备证书后 MinIO 有真实 PDF 对象。
- 证书临期进入工作中心预警。
- 检测员领用库存并关联工作单。
- 报告发放后自动生成归档项，档案管理员可核对并下载档案包。

### TODO-P1-09 客户门户业务闭环

问题描述：

- 门户仍缺我的送检单详情、合同/协议列表、报告中心、付款状态、消息通知和账户信息。
- 无权限对象仍可能回退到列表或展示下载入口。

开发思路：

- 门户按客户日常工作拆为：送检单、项目、协议、报告、付款、消息、账户。
- 每个详情页有独立 403/404 状态。
- 门户首页指标和列表分页使用同一口径。

验收方案：

- 客户能查看本人送检单详情和状态。
- 客户能查看待确认协议并签署。
- 客户能查看报告中心，未付款显示锁定原因，付款后下载。
- 未授权 URL 不展示任何其他客户数据。

## 5. P2 可交付体验和生产化

### TODO-P2-01 统一文件服务和真实 MinIO 对象链路

问题描述：

- 当前 MinIO 中只有样品照片 smoke 对象；报告、合同、设备文件、凭证、档案包多数只有元数据。
- 样品照片 smoke 使用文本伪装 JPEG，不能代表真实上传能力。

开发思路：

- 建立通用 `/files` 上传接口，返回 `fileId`、`objectKey`、`sha256`、`sizeBytes`、`contentType`。
- 后端校验文件魔数和 MIME，不允许文本冒充图片或 PDF。
- 报告 PDF、合同、凭证、设备文件、原始记录附件、档案包统一通过文件服务落 MinIO。
- 下载统一走授权接口。

验收方案：

- 上传真实 JPEG、PDF、DOCX。
- MinIO 对象字节、数据库 hash 和 API 返回一致。
- 错误 MIME 被拒绝。
- 各业务模块能通过 `fileId` 关联并下载。

### TODO-P2-02 路由、页面契约和 403/404 体验统一

问题描述：

- 多个直接路由和菜单/文档不一致，例如报告模板路由、客户主数据路由、系统治理命名。
- 未知路由静默回工作中心，不利于用户和测试。

开发思路：

- 对齐 `07_API与界面契约.md` 中全部内部和门户路由。
- 所有一级菜单支持刷新、复制链接、直接打开。
- 未知路由显示 404；无权限显示 403。
- 补齐报告模板页面路由。

验收方案：

- Playwright 遍历所有一级菜单深链。
- 未知内部/门户路径显示 404。
- 无权限详情显示 403，不展示全量列表。

### TODO-P2-03 状态守卫和动作按钮治理

问题描述：

- 已关闭阻塞、已禁用文件、已覆盖预约、已成功任务仍可能展示重复动作。

开发思路：

- 后端状态机先保证非法动作返回业务错误。
- 前端按状态隐藏或禁用不可用动作，并显示原因。
- 所有动作保持幂等或明确拒绝重复执行。

验收方案：

- 已关闭阻塞不能再次关闭。
- 已禁用设备文件不能再次作废。
- `NEEDS_RESCHEDULE` 预约不能重复覆盖。
- `SUCCESS` 导入导出任务默认只能下载/查看结果。

### TODO-P2-04 业务化展示替代 UUID/JSON/内部码

问题描述：

- 归档、设备文件、导入导出、报告日志等页面仍偏调试台，业务用户难以使用。

开发思路：

- 主表展示业务编号、客户、样品、报告号、状态、下一步动作。
- UUID、JSON 参数、内部状态码放入详情折叠区。
- 导入导出任务提供表单化参数，不要求用户手写 JSON。

验收方案：

- 档案管理员不看 UUID 也能定位项目档案。
- 设备管理员不手填 fileId 也能上传文件。
- 导入导出任务参数可通过表单创建。

### TODO-P2-05 工作中心从统计页升级为行动中心

问题描述：

- 工作中心已有统计、阻塞和趋势，但还未成为岗位用户每天处理工作的入口。

开发思路：

- 为不同角色显示不同待办和风险。
- 支持从风险、阻塞、待办直接跳转到项目、工单、报告、付款或设备预约。
- 趋势快照和人员负荷应有稳定生成逻辑。

验收方案：

- 销售看到待受理/待合同。
- 检测员看到本人超期工单。
- QC/QA/SD 看到待审。
- 财务看到付款锁定。
- 点击工作中心卡片能进入对应业务对象。

### TODO-P2-06 生产部署和运维可观测性

问题描述：

- 可交付系统需要可备份、可恢复、可审计、可定位问题。

开发思路：

- 明确 MinIO bucket 策略、生命周期、备份、恢复演练。
- 增加应用健康检查、日志关联 ID、关键动作审计报表。
- 提供部署后 smoke、回滚、数据备份和恢复步骤。

验收方案：

- 备份恢复演练通过。
- 任意报告下载可追溯请求、用户、报告、文件对象和发放日志。
- 部署手册能独立指导新环境上线。

## 6. 建议执行顺序

第一批必须连续完成：

1. TODO-P0-01 门户客户数据隔离和 IDOR 防护。
2. TODO-P0-02 正式报告 PDF 下载授权和发放审计闭环。
3. TODO-P0-05 动作接口权限、资源和请求体校验顺序统一。
4. TODO-P0-04 系统管理员用户、角色和组织治理。
5. TODO-P0-03 内部岗位数据范围收敛。

第二批按岗位闭环推进：

1. 文件服务和真实 MinIO 对象。

3. 工作中心行动化。
4. 运维可观测性和备份恢复。

## 7. 后续 goal 模式模板

每个 TODO 开发时使用以下结构：

```text
Goal: 本轮完成后最终用户能做什么。
Problem: 当前复测中确认的具体问题。
Scope: 本轮允许改哪些后端、前端、脚本和文档。
Implementation: 具体服务、接口、页面、数据模型和测试脚本怎么改。
Verify: 本地命令、API 脚本、Playwright、CI 和人工验收点。
Exit: 何时可以提交、PR、CI、合并。
```

不允许在一个 goal 中混修无关模块；安全修复可以横切多个接口，但必须有统一验收脚本。
