# 角色权限与审批规则

## 1. 角色设计原则

一期角色应服务于真实审批和业务分工。角色可以先按岗位建立，人员和组织架构后续补齐。涉及强制审批的角色不得省略。

角色与岗位是 N:N 关系。一个自然人可以同时拥有多个角色，例如同一人员可同时是设备管理员、标准品管理员和文件管理员；系统审批时按角色授权，不按岗位名称硬编码。

系统管理员只维护配置和账号，不默认拥有业务审批权。确需参与业务审批时，应额外授予对应业务角色。

## 3. 权限矩阵

权限矩阵以 `specs/permission_matrix.csv` 为权威，格式为 `actionCode,roleCode,access,scope,note`。

权限约定：

- `ALLOW`：允许操作。
- `READ`：只读查看。
- `DENY`：禁止。
- `CONDITIONAL`：有业务条件，例如付款后、本人项目、本单位项目。

开发时不得根据中文按钮名判断权限，必须根据 `actionCode + roleCode + scope` 判断。

## 4. 审批流程

### 4.1 非标方法报价前审批

流程：

非标申请 → 技术评审 → 成本评估 → 周期评估 → 技术负责人审批 → 业务负责人审批 → 允许报价。

系统规则：

- 技术负责人未审批通过，业务负责人不能最终通过。
- 任一审批驳回，项目回到评审修改状态。
- 审批通过前禁止正式报价。
- 审批通过前禁止合同签署。

### 4.2 合同评审

合同评审应覆盖：

- 项目是否在能力范围内。
- 是否属于 CMA/CNAS 资质范围。
- 客户要求是否明确。
- 方法、设备、人员是否满足。
- 是否需要分包。
- 是否能按期完成。
- 是否存在非标或特殊风险。
- 费用和付款条件是否明确。

合同评审通过后方可进入签署。

### 4.3 方案审批

方案审批规则：

- 所有项目必须走 SD。
- GLP 项目必须走 QA。
- 动物试验必须走伦理委员会。
- 方案未完成必要审批，不得正式试验下发。

### 4.4 试验下发审批门禁

正式下发前系统校验：

- 合同或协议已签署。
- 样品已接收并核验通过。
- 样品已入库或完成必要流转。
- 方案审批已完成。
- 置样任务已完成或确认无需置样。
- 动物试验伦理审批已通过，如适用。

校验失败时，任务状态只能为待下发或资料未完备，不允许进入试验执行。

### 4.5 原始记录审核

原始记录应由非同一检测人员进行审核。审核规则：

- 检测员提交原始记录和结果。
- 审核人检查记录完整性、计算、设备、环境、样品和结果。
- 不通过时退回检测员修改。
- 通过后允许报告编制。

### 4.6 报告审核和签发

报告流程固定：

报告编制 → QC 技术审核 → QA 质量审核 → SD 最终审核 → 授权签发 → 付款门禁 → 报告发放。

系统规则：

- 任一节点驳回，退回报告编制。
- 报告签发后应锁定关键内容。
- 正式报告发放受付款门禁控制。
- 作废和重新签发必须留痕。

### 4.7 付款门禁

付款门禁的触发源是收款记录。财务人员或出纳登记到账并上传凭证后，系统按项目或报告汇总付款状态，自动解锁对应报告发放和样品处置动作。

未付款或未到账时禁止：

- 打印正式纸质报告。
- 下载正式 PDF 报告。
- 发放电子签章报告。
- 样品退还、回寄或销毁。

未付款时允许：

- 试验执行。
- 结果录入。
- 报告编制。
- 草稿报告预览。

规则：

- 业务员、检测员、报告编制员不得手工改付款状态。
- 前端不得通过隐藏按钮代替付款门禁，后端下载和发放接口必须二次校验。
- 收款记录冲销后，应重新计算付款门禁状态。
- 绿色通道不等同于已付款，只解锁审批指定范围。

### 4.8 绿色通道审批

流程：

业务发起绿色通道申请 → 部门负责人审批 → 管理层 / 总经理审批 → 系统临时解锁 → 电子正式报告发放。

规则：

- 仅解锁电子正式报告。
- 纸质报告必须到账后才能打印。
- 样品退还仍受付款规则控制，除非另行审批。
- 申请、审批、解锁、发放必须归档。

### 4.9 设备预约冲突处理

规则：

- 检测员可提前 7 天预约。
- 外部用户可提前 2 天预约。
- 最小预约单位半小时。
- 内部预约可覆盖外部预约。
- 覆盖必须记录原因、操作人、时间和被覆盖预约。

### 4.10 统一变更审批

统一变更中心覆盖协议、样品、项目、报告等关键字段变更。它替代旧系统中分散的协议变更申请和样品变更申请菜单，但不降低审批要求。

规则：

- 变更申请必须记录目标对象、字段路径、原值、新值、申请原因和附件。
- 未签署合同、未签发报告前的低风险变更，可由目标对象负责人审批后生效。
- 合同签署后、报告签发前的关键字段变更，必须经业务负责人、技术负责人或质量负责人按变更类型审批。
- 已签发报告、已归档项目等硬锁对象，不允许直接覆盖历史字段；应进入报告重新签发、补充协议或只读归档更正流程。
- 变更审批通过后由后端领域服务统一生效，不允许前端直接调用目标对象更新接口绕过 `change_request`。
- 每次生效必须写入 `audit_log`，并在目标对象详情展示变更历史。

### 4.11 留样和设备文件权限

留样和设备文件属于合规辅助对象，不是普通附件。

规则：

- 样品管理员可登记留样和发起处置，质量负责人可监督和复核异常处置。
- 留样退还、销毁仍受付款门禁和项目状态约束。
- 设备管理员可上传、更新和作废设备文件，质量负责人可查看和监督证书有效期。
- 检测员只能查看与本人工作单相关设备的必要文件状态，不得修改设备文件。
- 证书、校准、检定类文件过期时，工作中心必须预警；是否禁止使用设备由业务规则配置决定。

### 4.12 报告模板、注册中心和导入导出权限

规则：

- 报告编制员可选择已发布模板生成草稿，但不得发布模板。
- 报告模板发布和废止由质量负责人或系统管理员执行，模板发布不代表报告内容审批。
- 报告注册中心允许质量负责人、档案管理员和授权报告角色查询；正式报告下载仍受付款门禁控制。
- 批量下载报告必须生成导出任务，记录操作人、范围、文件哈希和过期时间。
- 导入任务必须先预校验，确认导入仅允许系统管理员或质量负责人执行。
- 普通列表导出、迁移导入、审计导出应使用不同 `actionCode`，不得用一个通用导出权限覆盖全部场景。

## 5. 数据权限

建议一期按以下原则控制数据范围：

- 客户只能看本单位项目。
- 业务员可看本人负责客户和项目。
- 技术负责人可看所辖技术项目。
- 检测员可看分配给自己的工作单和必要样品信息。
- QA、QC、SD 可看待审核项目和历史审核记录。
- 样品管理员可看样品相关信息。
- 设备管理员可看全部设备预约。
- 标准品管理员可看标准品和耗材台账。
- 档案管理员可看归档后的报告和发放日志，但不修改报告正文。
- 质量负责人可查看统一变更、留样、设备文件和报告注册中心，用于监督和复核。
- 管理层可看全局统计和关键项目。
- 系统管理员维护配置，不默认参与业务审批。

## 6. 审批记录要求

所有审批记录必须包含：

- 审批节点。
- 审批人。
- 审批角色。
- 审批时间。
- 审批结论。
- 审批意见。
- 驳回原因，如适用。
- 关联项目、合同、样品、报告或设备预约。

审批记录不得物理删除。确需作废时，应使用作废状态并保留原记录。
